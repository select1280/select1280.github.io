# 網站維護約定

適用於 select1280 個人 GitHub Pages。採按需更新、定期檢查；不為了維持頻率而強制增加功能。首次訂定：2026-11-24。

## 每次發布

1. 在功能分支開發，提交訊息使用中文。執行 npm test、npm run build、npm run check。
2. 本機以桌面與手機寬度確認首頁、導覽、天氣展開、圖鑑開關與鍵盤操作；抽查遊戲及工具。記錄未完成的人工驗證。
3. 海洋功能有修改時，確認探索完成才收藏、重播不計次、重新整理仍保留收藏、區域解鎖及減少動態模式。完整集滿流程的規則由測試驗證，人工抽查動畫。
4. 確認內容與航行日誌同步後，合併 main 並推送。GitHub Actions 全部成功後，再確認線上版本與桌面／手機主要操作。
5. 發布出現嚴重問題時，優先使用 git revert 回退對應提交並重新發布，保留歷史。部署成功不代表視覺驗證已完成。

## 每月一次：第一個週末，約 20–30 分鐘

- 確認網站、分頁、GitHub 連結與 Actions 狀態正常。
- 抽查 Open-Meteo 天氣、切換城市、失敗重試及舊資料提示；確認資料來源連結仍可使用。
- 用桌面及手機檢查天氣標籤與海洋外框間距、圖鑑捲動、對話框、Hover 與觸控。
- 檢查已發現的問題，整理下一次修正；無問題時毋須重新發布。

## 每季一次：約 1 小時

- 檢查 Node.js 支援狀態與 GitHub Actions 各動作版本、安全公告；依官方文件評估更新，完成測試後才升級。
- 檢查載入速度、動畫負擔、鍵盤操作、對比與減少動態模式。
- 檢視作品、工具說明及航行日誌是否仍符合現況；新增有價值的作品，不追求每季固定新增遊戲。
- 收藏資料格式若要變更，先設計版本與遷移，避免清除既有收藏。localStorage 不是跨裝置備份，不加入秘密或個人敏感資料。

## 臨時問題

網站無法開啟、主要操作失效或收藏進度受損：發現後優先處理，必要時先回退。一般視覺微調可集中到下一次更新。這是處理優先順序，不代表有全天候自動監控或保證修復時限。

## 分工與執行

- GitHub Actions 負責每次推送 main 後的測試、建置、連結檢查與部署。
- 網站擁有者安排每月／每季檢查並提出更新需求；助手在被要求時協助檢查、修改及發布。
- 本約定未建立自動提醒、定期排程或背景監控。若之後需要，再另外設定通知方式與頻率。

## 維護紀錄格式

日期、檢查項目、結果、待辦、對應提交或 Actions 連結。例：2026-11-24／發布檢查／通過或待確認／手機圖鑑需複查／提交 SHA。
